# Maya シーンビューア（簡易版）

Maya ASCII（.ma）のモデル形状・ジョイント・スキンウェイト・アニメーション・カメラを、Maya なしで確認するためのビューアです。
表示は three.js、ウィンドウは PySide6（QtWebEngine）で作られています。Maya 内でも起動でき、その場合は Maya で開いているシーンをそのまま表示します。

シーンの完全な再現は目的にしていません。アニメーションは、キー（アニメーションカーブ）と、主なコンストレイント・IK（回転プレーン・シングルチェーン・スプライン）・計算ノード・キャラクターセット（Trax のクリップを含む）で動く移動・回転・スケールと、表示（visibility）・カメラの属性を再生します（Maya と同じ考え方の近似。対応範囲は「対応範囲と制限」）。表示するのはポリゴンメッシュ・ジョイント・NURBS カーブ・カメラで、NURBS サーフェスなどは表示しません。

## できること

- **形状の確認**: ポリゴンメッシュの表示（スムーズ／フラット／ワイヤーのみ）。Maya のハードエッジ（スムーズでない辺）では陰影を切って、角を立てて表示します。ワイヤーはポリゴン本来の辺で表示し、三角形分割の対角線は出ません。
- **ライト**: 標準（カメラに追従する平行光と環境光）と、フラット（ライトの影響なし。Maya のフラットライトと同じく、テクスチャやマテリアルの色をそのまま表示）を切り替えられます。
- **骨の確認**: ジョイントの階層と位置を Maya 風の骨の形で表示します（初期状態では非表示。J キーかツールバーのジョイントのアイコンで切り替え）。ローカル軸（選択中のジョイントのみ、またはすべて）も表示できます。
- **カーブの表示**: NURBS カーブ（コントローラーの形・スプライン IK のカーブなど）を線で表示します。色は Maya の描画のオーバーライド（色番号・RGB）とディスプレイレイヤーの色を使い、指定がなければ明るい灰色です。テンプレート表示は灰色、非表示のシェイプと中間オブジェクトは描きません。カーブをクリックすると、その transform を選択します（テンプレート・リファレンスのカーブは、Maya と同じくクリックでは選びません）。ツールバーのカーブのアイコンで表示を切り替えられます。アニメーションやコントローラーの移動にはそのままついていき、skinCluster や制御点の接続で形が変わるカーブは、変形した形で表示します。
- **選択**: ビューポートのクリックで選ぶものを、ツールバーで「オブジェクト」（既定）と「頂点」から選べます（F8 で切り替え）。オブジェクトの選択では、クリックしたメッシュの transform を選び、そのメッシュを選択の色のワイヤーで強調します。頂点の選択では、いちばん近い頂点のウェイトを表示します。
  - **Maya での選択の可否**: Maya のビューポートで選べないもの（テンプレート、描画のオーバーライドやディスプレイレイヤーの表示の種類がテンプレート・リファレンスのもの。祖先の設定も引き継ぐ）は、クリックしても選びません（階層の一覧からは選べます。選択情報に理由を表示）。ツールバーの鍵のアイコン「選択の制限を無視」をオンにすると、これらもクリックで選べます。
- **表示・非表示**: 階層の各行の目のアイコン（または H / Ctrl+H / Shift+H）で、ノードごとに表示を切り替えられます。Maya と同じく、ノードを隠すとその下のメッシュとジョイントも隠れます。Maya で非表示のノードは、非表示の状態で読み込みます。
  - **リグで切り替える表示**（.ma から読み込んだとき）: コントローラーの独自の属性（geoVis など）や計算ノード（reverse・condition など）、キーで決まる表示（.v・.lodv・描画のオーバーライドの .ovv）も、アニメーションを読み込むとフレームごとに評価します（シェイプの表示も対象）。リグで隠れているノードも、目のアイコンで表示し直せます。
- **シーンのカメラ**: シーンにあるカメラ（起動時からある persp・top・front・side は除く）を、ツールバーの［カメラ］か C キーで選んで、そのカメラから見られます（Shift+C で自由視点に戻す）。焦点距離・フィルムバック・フィルムフィット・フィルムオフセット・クリップ面・平行投影を再現し、レンダーの解像度（defaultResolution）の縦横比で解像度ゲートを表示します（外側を暗くする）。カメラのアニメーション（移動・回転・コンストレイント・焦点距離のキーなど）にもついていきます。自由視点ではカメラの形（視野の四角錐）を表示します。
  - **カメラのビューを動かす**: 再生していないときは、カメラから見たままドラッグ・ホイールで視点を動かせます（いまのフレームのカメラの位置・向きから。焦点距離・解像度ゲートはカメラのまま）。表示だけで、ファイルには保存しません。フレームを動かすか再生すると、カメラの位置に戻ります。再生中は動かせません。動かし始めると視線まわりの傾き（ロール）はなくなります。
  - **開いたときのカメラ**: 保存したときに Maya のビューで見ていたカメラから表示します（.ma の画面構成の「Current Layout」の最初のビュー。Maya 内では作業中のビュー）。persp など起動時のカメラなら自由視点です。
- **カメラシーケンサ**: シーンにショット（shot）があると、ビューポートの上にカメラシーケンサのパネルを出します（再生ボタンなどの操作の行はトラックの下に置き、ツールバーとも下端のシーンのタイムラインとも離しています。シーケンスの再生ボタンは紫）。トラックごとにショットの並び（ショット名・カメラ・範囲）を表示し、再生ボタン・ショット送り・シーケンスのフレームで確認できます。トラックの上をクリック・ドラッグするとそのフレームへ移動し、ビューポートはそのショットのカメラとシーンのフレームで表示します（「シーケンスで見る」）。トラックは Maya と同じくトラック 1 を一番上に、2、3… を下の段に並べ、重なるショットは上の段（番号の小さいトラック）を使います。ミュートしたショットは使いません。scale・preHold・postHold も反映します。ショットの編集（並べ替え・長さの変更）はできません。シーンのタイムラインを操作したり、自分でカメラを選んだりすると、「シーケンスで見る」はオフになります。ショットのカメラが persp などの起動時のカメラでも、そのカメラを読み込みます。
- **姿勢の基準**: 読み込み直後は**バインドポーズ**で表示します（skinCluster の .pm → dagPose → ジョイントの .bps の優先順で、バインド時の姿勢を復元）。メッシュの元形状と骨がぴったり重なった状態から確認できます。ツールバーの**バインドポーズのボタン**（T ポーズの人のアイコン。押した状態がバインドポーズ）か B キーで「ファイルの値」（保存時のポーズ）と切り替えられます。キーのあるアニメーションを読み込むと、自動で「ファイルの値」に切り替わります（読み込みのあとで自分でバインドポーズを選んでいた場合はそのまま）。
- **テクスチャ・PBR のマップ**: ベースカラー・ノーマルマップ・ラフネス・メタリック・AO・エミッシブ・不透明度を表示します（TGA・PNG・JPEG など。UDIM にも対応）。ツールバーの［マップ］で、合成（PBR）表示と各マップの単独表示を切り替え、合成に使うマップを個別にオン・オフできます。ラフネスなどは、オンにしたときに初めて読み込みます。面ごとのマテリアルの割り当てにも対応し、アルファで透過（切り抜き・半透明）できます。テクスチャのパスは、書かれたパス → プロジェクトの sourceimages → .ma と同じフォルダ、の順に探します（詳細は「対応範囲と制限」）。左の［メッシュ］タブで、マテリアルごとのテクスチャの読み込み状況を確認できます。
- **スキンウェイトの確認**
  - 選択ジョイントのウェイトをヒートマップで表示します（0 = 青、1 = 赤、ウェイトなし = 暗い灰色）。
  - インフルエンスごとに色分けして、境界の混ざり具合を表示します。
  - 頂点の選択（ツールバーか F8）でメッシュをクリックすると、いちばん近い頂点のウェイト一覧を表示します（合計値・インフルエンス数つき）。
  - 9 つ以上のインフルエンスを持つ頂点、合計が 1 でない頂点、ウェイトのない頂点を数えて警告します。
- **ポーズ確認**: ジョイントやトランスフォームを、ビューポートのハンドル（W: 移動、E: 回転、R: スケール）か、右パネル［選択］のポーズ確認欄（移動・回転・スケールの数値）で動かし、ウェイトによる変形を確かめられます。動かした量はローカル軸が基準で、表示だけに使い、ファイルには保存しません。変更は元に戻す・やり直すことができます（Ctrl+Z / Ctrl+Y）。親ジョイントをスケールしたときは、Maya の segmentScaleCompensate と同じく、子の位置だけが伸びて子自身は拡大されません。
- **アニメーションのプレビュー**（.ma から読み込んだとき）: ジョイントやトランスフォームの移動・回転・スケールのキーを再生します（キャラクターセットのキーと Trax のクリップも再生します）。ビューポート下端のタイムラインで、再生・停止（Alt+V）、フレームの移動（スライダー・数値）、コマ送り（Alt+, / Alt+.）、キー送り（, / .）ができます。再生範囲は Maya の設定（playbackOptions）を使い、タイムラインで変えられます。スキンの変形も一緒に動き、ポーズ確認で加えた変更はアニメーションの上に重なります。
  - アニメーションは「ファイルの値」の姿勢で再生します（読み込んだときと、タイムラインを操作したときに自動で切り替わります）。バインドポーズのボタン（B）でバインドポーズに戻すと、どのフレームにいても同じ姿勢になります。バインドポーズの情報がないノード（一番上のグループなど）は、保存したときのフレームの値で表示します。
  - **リグ**: コンストレイント（point・orient・parent・scale・poleVector・aim、カメラとエイムの lookAt）、IK（回転プレーン・シングルチェーン・スプライン。ジョイントの数は問わない）、計算ノード・行列ノード・四元数ノード・ドリブンキー・アニメーションレイヤー・expression などで動くノードも評価します（一覧は「対応範囲と制限」の「リグ」）。コントローラー（ジョイント・メッシュ以外でリグを動かすノード）は、黄緑の八面体で表示します（ジョイントの表示と連動）。ポーズ確認でコントローラーを動かすと、IK やコンストレイントが追従します（例: 手のコントローラーを動かすと腕が曲がる）。キーがなくリグだけのシーンでも、タイムラインは出さずに評価します。
  - **読み込みは 2 段階**です。シーン（メッシュ・骨）を先に表示し、アニメーションはそのあと裏で読み込みます。アニメーションのない .ma や、アニメーションを読まない設定（［ファイル］→［アニメーションを読み込む］）では、表示までの時間は変わりません。
  - 補間は Maya に近い近似です（詳細は「対応範囲と制限」）。
- **再生のフレームレート**: ビューポートの右下（ヘッドアップディスプレイ）に、再生中は実際に表示できたフレーム数（直近 1 秒）とシーンのフレームレートを「再生 23.9 / 24.0 fps」のように 1 行で表示します。描画が間に合わずに目標の 9 割を下回ると赤く表示します（再生は実時間なので、間に合わないフレームは飛ばします）。停止後は「直前の再生 23.9 / 24.0 fps」と平均を表示します。［表示］メニューで表示を切り替えられます。
- **Maya 連携**（Maya 内で起動したとき）
  - 現在のシーン全体、または選択範囲だけを読み込めます。
  - ビューアで選んだノードを Maya でも選択し、Maya の選択にもビューアが追従します。
  - カメラ・カメラシーケンサのショット・作業中のビューのカメラ・選択の可否も、Maya の状態から読み込みます（アニメーションは読み込みません）。

## 必要なもの

| 用途 | 必要なもの |
|---|---|
| スタンドアロン | Python 3.9 以降、PySide6 6.5 以降（`pip install -r requirements.txt`） |
| Maya 内 | Maya 2025 以降（同梱の PySide6 に QtWebEngine が含まれていること） |
| コマンドライン変換のみ | Python 3.9 以降（追加パッケージ不要） |

.ma の解析は純 Python なので、numpy などは不要です。

## 使い方

### スタンドアロン

```
pip install -r requirements.txt
python run_viewer.py                 # 空のウィンドウで起動
python run_viewer.py scene.ma        # ファイルを指定して起動
```

起動後は［ファイル］→［開く］（Ctrl+O）を使うか、.ma をウィンドウにドロップして開きます。F5 で同じファイルを読み直します。

### Maya 内

**シェルフに登録する（おすすめ）**: `install_maya.py` を Maya のビューポートにドラッグ＆ドロップすると、現在のシェルフにボタンが追加されます。

**スクリプトエディタから起動する**:

```python
import sys
sys.path.append(r"C:/tools/maya_ma_viewer")   # このフォルダの場所
import ma_viewer.maya_launcher as mv
mv.show()                 # 現在のシーンを表示
mv.show("selection")      # 選択したノード以下だけを表示
mv.show(None)             # 空のウィンドウ（.ma を開く用途）
mv.reload_and_show()      # 開発用: コードを読み直してから開く
```

［Maya］メニューで、読み込みのやり直しと、選択の同期（ビューア→Maya、Maya→ビューア）のオン／オフを切り替えられます。

### コマンドライン

```
python -m ma_viewer info scene.ma              # 内容の概要と警告を表示
python -m ma_viewer export scene.ma -o out.json   # 共通 JSON に変換（アニメーションも含む。--no-animation で除く）
python -m ma_viewer view scene.ma              # ビューアで開く
python -m ma_viewer rig scene.ma               # リグの診断（評価できないノードと、IK の極ベクトルなどの上流）。-o で保存
```

**リグの診断**: 再生した姿勢が Maya と違うとき（IK のアップベクターが反転するなど）の原因探しに使います。Qt 版は［表示］→［リグの診断…］です。次の内容を一覧にします。

- ファイルが読み込むプラグイン（requires）と、transform として扱った自作ノード。
- **自作のトランスフォームノード**: 型を知らないノード（プラグインの自作ノード）でも、transform らしい証拠（親や子がある・移動 / 回転 / スケールの値がある・ワールド行列などを出力している・移動などに接続がある）があれば、通常の transform として扱って評価します（警告に一覧を出します）。
- 評価できないノード（未対応の型・自作ノード・解釈できない expression）と、それを使っているノードの属性。
- IK ハンドルごとの上流のつながり：ハンドルの位置・極ベクトル・ひねり・開始ジョイントの親が、何で決まっているかを示します。行頭の ✓ は評価できる、★ は評価できない（そこから先の値はファイルに保存された値のまま）という意味です。
- 読み込まないカーブ（表示していないノードを動かすもの）: 動かすノードから下流へすべての接続をたどり、表示するノードやリグに届くかを調べます。届く場合は ★ と経路を出します（こちらのたどり方の漏れか、評価できないノードを経由しているため、再生に影響します）。届かないものは ✓ で、再生には影響しません（カメラ・使っていないコントローラーなど）。
- 値を求められないノード（バインドポーズの形で推定・推定できない）と、警告の全文。
- （Qt 版のみ）**保存時のフレームの再現チェック**: .ma に保存されたジョイントの回転は、保存したときに Maya が IK を解いた結果です。保存時のフレームでビューアが解いた IK の結果とこれを比べ、IK ハンドルごとに、ジョイントのずれの角度を「ねじれ（骨の軸まわり）」と「曲がり（骨の向き）」に分けて出します。★ があれば、その IK の解き方が Maya と合っていません（極ベクトル（ワールド）とひねりの値も出します）。比べるのはファイルに書かれた回転です（移動がコンストレイントで決まるジョイントは、表示用にはバインドポーズへ置き換えますが、保存された回転はそのまま使います）。ずれがある IK は、解き方の候補（ひねりの向き：今の向き・逆・使わない、極ベクトルの空間：ハンドルの親・ワールド・開始ジョイントの親、肘の側：極ベクトルの側・反対側、スプライン IK のひねりの配り方）を総当たりで試し、ファイルの値に一番合うものと、それで一致する IK の数を出します。終端がハンドルに届いていない場合（ハンドルを動かすリグの側のずれ）と、肘（膝）の向き（ファイルの姿勢から逆算した、Maya が使った極ベクトル＋ひねりの向きと、こちらの値の差。ずれていれば、極ベクトル・ひねりを決めるノードの評価が Maya と違う）も出します。さらに、開始ジョイントの親がファイルの値からずれていないかと、ずれ始めるノード（ルートから順に比べて最初にずれるノード。別の IK で動くならその名前）を出します。親がずれていれば、その IK ではなく親の側（たとえば背骨のスプライン IK）が原因です。極ベクトル・ハンドルの位置・ひねりが、その IK で回るジョイント（またはその子）に依存している（循環）場合も ★ で示します（Maya は 1 つ前の評価の値で解くため、保存された姿勢と入力の値が食い違います）。極ベクトルのコンストレイントの開始の位置の材料（crp・crt・ps の接続元または値）も出します。キーやコンストレイントで決まる成分はファイルに値がないため、評価した値を使って比べます。

**自作ノードの割り当て**: 自作ノード（プラグイン）の中の計算は .ma に書かれていないため、そのままでは評価できません。同じ計算をする標準ノードがあれば、設定ファイルで割り当てると評価できます。リグの診断に、評価できないノードの型ごとの雛形（つながっている属性名入り）を出すので、「as」と属性名の対応を書き換えて保存し、開き直してください。

```json
{
  "myMatrixBlend": {"as": "multMatrix", "attrs": {"inMatrix": "i[0]", "outMatrix": "o"}},
  "myCtrlTransform": {"as": "transform"}
}
```

- 置き場所（後のものが優先）: `~/.ma_viewer/nodes.json`、環境変数 `MA_VIEWER_NODES` のパス、.ma と同じフォルダの `ma_viewer_nodes.json`。
- 「as」: ビューアが評価できる型（multMatrix・inverseMatrix・decomposeMatrix・composeMatrix・multiplyDivide・plusMinusAverage・transform など）。
- 「attrs」: 自作ノードの属性名 → 標準ノードの短い属性名。`"i"` のように添字なしで書くと元の添字を引き継ぎ（inMatrix[2] → i[2]）、`"i[0]"` のように添字つきで書くとその属性になります。行列を扱う主な型の属性: multMatrix は入力 `i[k]`・出力 `o`、inverseMatrix は `imat` → `omat`、decomposeMatrix は `imat` → `ot`・`or`・`os`・`oq`、composeMatrix は `it`・`ir`・`is` → `omat`。

出力はテキストなので、そのまま貼り付けて相談できます（ファイル本体を渡さなくても、原因の見当がつきます）。

### exe にする（1 ファイル）

PyInstaller で、Python のない PC でも動く 1 ファイルの実行ファイルを作れます。exe は作った OS 用になるので、Windows 用の exe は Windows 上で作ってください。

```
pip install pyinstaller
python packaging/build_exe.py          # → dist/MayaSceneViewer.exe
```

設定は `packaging/maya_ma_viewer.spec` にあります。ビューアの画面ファイル（`ma_viewer/web` の index.html・style.css・viewer.bundle.js）は Python のコードではないため、spec でデータとして同梱しています。実行時は一時展開フォルダ（`_MEI…`）の `ma_viewer/web` に置かれ、`ma_viewer/resources.py` がそこを見つけます。

**自分で PyInstaller のオプションを指定する場合**は、画面ファイルを必ず同梱してください（区切りは Windows では `;`、それ以外では `:`）。

```
pyinstaller --onefile --windowed --name MayaSceneViewer --add-data "ma_viewer/web;ma_viewer/web" run_viewer.py
```

同梱先が `web` でも見つかるようにしてあります。画面ファイルが見つからない場合は、探した場所と対処法をダイアログで表示します。環境変数 `MA_VIEWER_WEB_DIR` で場所を指定することもできます。

**動作確認**: できた exe に `--selftest` を付けると、ファイルを読み込んで結果を書き出し、自動で終了します。

```
dist\MayaSceneViewer.exe samples\sample_arm.ma --selftest --selftest-out selftest.json
```

`selftest.json` の `"ok"` が `true` なら、画面ファイルの読み込み・シーンの表示・WebGL の初期化まで成功しています（`webDir` に、実際に使った画面ファイルの場所が入ります）。

### ブラウザで見る（確認・不具合調査用）

`ma_viewer/web/index.html` をブラウザで直接開き、［JSON を開く］で `export` した JSON を読み込めます。Qt を使わずに表示部分だけを確認したいときに使います。

## 対応範囲と制限

**.ma から読み込む場合**

- **ヒストリは削除して保存してください。** polyCube などの作成ノードから形状が作られているメッシュは、頂点データがファイルにないため表示できません（警告を出して除外します）。
- スキン付きメッシュは、変形後シェイプから groupParts・tweak を経由して元形状（〜Orig）までさかのぼって特定します。tweak の頂点オフセットも反映します。
- skinCluster 以外のデフォーマ（blendShape、deltaMush など）の効果は反映しません（警告を出します）。
- 対象外のもの: リファレンス（`file -r`）の中身、インスタンス（`parent -add`）、Maya バイナリ（.mb）。
- 作業単位は cm を前提にしています。それ以外の単位では、ファイルに書かれた値のまま表示します（警告を出します）。角度は度・ラジアンのどちらにも対応します。
- 穴付きの面は、穴を無視して表示します。
- **接続で値が決まる属性**は、.ma に値が残っていません。アニメーションカーブと、下の「リグ」で評価できるものは、アニメーションを読み込むと評価した値で表示します。それ以外（エクスプレッションなど）で決まるノードは、バインドポーズの情報があれば「ファイルの値」でもその姿勢で表示し、なければ既定値（移動 0・回転 0）で表示します。どちらの場合も警告を出し、選択情報に接続元を表示します。
- **ディスプレイレイヤー**: 非表示のレイヤー（.v が off）に入っているノードは、非表示で読み込みます（レイヤーが無効なら影響しません）。レイヤーの表示そのものが接続で決まる場合は評価しません。
- **接続で決まる表示（visibility）**: .ma に値が残らないため、アニメーションを読み込むまで（または［アニメーションを読み込む］がオフのとき）は表示のままです。読み込むと、カーブと下の「リグ」で評価できるノードから求めた値で表示します。評価できないノード（エクスプレッションの一部など）を経由する場合は、ファイルの値のまま表示します。
- **選択の可否**: テンプレート（.template）と、描画のオーバーライドかディスプレイレイヤーの表示の種類（テンプレート・リファレンス）から決めます。選択マスク・選択の優先度・ロックしたノードなど、ほかの選択の設定は見ません。
- **カメラ**: 再現するのはカメラの視点と投影です。被写界深度・オーバースキャン・パンとズーム（2D パン）・イメージプレーン・カメラの注視点（camera and aim の aim）・ステレオカメラの左右のずれは反映しません。カメラの属性のうち、接続・キーで値が決まるもの（焦点距離など）は、アニメーションを読み込むと評価します。
- **カメラシーケンサ**: ショット（shot）のシーンの範囲・シーケンス上の開始・scale・preHold・postHold・トラック・ミュート・カメラを読みます。シーケンス上の終わりは、開始 + preHold + (終了 − 開始) × scale + postHold で求めます。オーディオ・クリップ（映像）・トランジション・ショットごとの解像度は使いません。
- **開いたときのカメラ**: 画面構成のスクリプト（uiConfigurationScriptNode）の「Current Layout」で最初のビューのカメラを使います。複数画面のレイアウトでは、どのビューで作業していたかは分からないため、最初のビューになります。
- **Trax・カメラシーケンサの .ma の書式**: 実際の Maya のファイルでの確認ができていないため、Autodesk のドキュメントから推定した書式で作ったサンプルで確認しています（属性は短い名前・長い名前のどちらでも読みます）。
- **offsetParentMatrix**（Maya 2020 以降）は、ファイルの値をローカル行列のあとに掛けます（ワールド行列 = ローカル · offsetParentMatrix · 親）。接続で決まる場合は、アニメーションを読み込むと評価した値を使います。

**アニメーション（.ma から読み込む場合）**

- 再生するのは、表示するノード（メッシュ・ジョイント・インフルエンスとその親）の移動・回転・スケールです。値は、アニメーションカーブ（animCurveTL・TA・TU）と、下の「リグ」で評価できるノードから求めます。
- 移動・回転・スケールのほかに、表示（.v・.lodv・.ovv）と、カメラの属性（焦点距離・フィルムバック・クリップ面など）のカーブ・接続も評価します。
- **キャラクターセット**（character）も再生します。カーブがキャラクターセットの属性に直接つながる場合はその値を、Trax のクリップ（clipLibrary・clipScheduler・animClip）の場合は、各クリップの開始・ソースの範囲・スケール・前後のサイクル・hold・ウェイト・有効・トラックを読んで、そのフレームで有効なクリップの値を使います。クリップが重なるときは、あとから始まるクリップ（同じならトラックの番号が大きい方）を使い、クリップのない区間は直前のクリップの最後の値を保ちます。クリップ間のブレンド・相対（relative）クリップのオフセット・タイムワープは反映しません。
- 再生しないもの（警告を出します）: 下の「リグ」で評価できないノード（解釈できない expression・未対応のコンストレイントやノード・プラグインのノードなど）を経由する値。移動・回転・スケール・表示・カメラ以外の属性（マテリアルの色など）のカーブ。
- 補間: 重みなしのカーブは Maya と同じエルミート補間、重み付きのカーブは 3 次ベジエです。接線の種類のうち、リニア・フラット・ステップ・ステップ（次）・固定（kix などの値）は値どおりに、スプライン・クランプ・オート・プラトーは近似で計算します（オートとプラトーは山・谷で平らにし、キーの値を行き過ぎないようにします）。スロー・ファストはスプラインとして扱います。
- 範囲外（pre / post infinity）: 一定・リニア・繰り返し・オフセット付き繰り返し・往復に対応します。
- 時間の単位（currentUnit -t。film・ntsc・pal・game・show・palf・ntscf と「○○fps」）と、再生範囲（sceneConfigurationScriptNode の playbackOptions）を読みます。再生範囲がなければ、キーのある範囲を使います。読み込み直後のフレームは、保存したときの現在のフレーム（time1）です。
- 再生は実時間です。描画が間に合わないときはフレームを飛ばします。
- Maya 内で読み込んだ場合は、アニメーションはまだ読み込みません。
- アニメーションを読み込んでいる間（2 段階目）と、［アニメーションを読み込む］がオフのときは、リグで決まる表示・カメラの焦点距離などは評価しません。

**リグ（.ma から読み込む場合）**

表示するノードの移動・回転・スケールの接続を上流へたどり、評価に必要なノードを洗い出します（1 段階目。接続だけを見るので軽い処理です）。コントローラーなどの DAG ノードは階層にも表示します。属性の値は 2 段階目で読み、評価はビューアで行います（`web_src/src/rig.js`）。Maya と同じ考え方の近似で、細部は Maya と違うことがあります。

| 種類 | 内容 |
|---|---|
| pointConstraint | ターゲットの回転ピボットの重み付き平均 + オフセット（.o） |
| orientConstraint | ターゲットのワールドの向きの重み付き平均（四元数）· オフセット（.o） |
| parentConstraint | ターゲットごとに（ターゲット · オフセットの移動 · オフセットの回転）を求め、位置と向きを重み付き平均 |
| scaleConstraint | ターゲットのワールドのスケールの重み付き平均 × オフセット（.o） |
| poleVectorConstraint | ターゲットの位置 − 開始の位置（IK ハンドルの極ベクトル）。Maya と同じく、開始の位置はコンストレイントの属性 (constraintRotatePivot + constraintRotateTranslate) を pivotSpace でワールドへ移したもの（ふつうは開始ジョイントの位置。crp がつながっていなければ親の原点などになる）、ターゲットの位置は (targetTranslate + targetRotatePivot + targetRotateTranslate) を targetParentMatrix で移したもの |
| lookAt（カメラとエイム） | Maya の［カメラとエイム］・［カメラ、エイム、アップ］のグループ。aimConstraint と同じ解き方（aim の既定はカメラの −Z）に、world up がシーンの上・ベクトルのときは twist（.tws）で視線のまわりに回す（ロール。回る向きは Maya では未確認）。twist はキー・別のノードの属性・カメラのシェイプの独自の属性からつないでもよい（独自の角度の属性 doubleAngle の値はラジアンに直して読む）。twist・オフセット・up などの補助の入力が未対応のノードにつながっているときは、その接続だけを外してファイルの値で評価する（エイムの向きは求め、警告を出す） |

| 計算ノード | unitConversion・pairBlend（成分ごとのモード・四元数の補間を含む）・blendColors・multiplyDivide・plusMinusAverage（1D・2D・3D）・reverse・condition・addDoubleLinear・multDoubleLinear・clamp・setRange・remapValue（値のランプ。補間なし・線形・スムーズ、スプラインはスムーズで近似）・distanceBetween（行列も使う）・vectorProduct（内積・外積・ベクトル × 行列・点 × 行列・正規化）・blendTwoAttr・blendWeighted・choice |
| ドリブンキー | animCurveUA・UL・UU（ドライバーの値 .i でキーを引く。角度のドライバーは Maya が挟む unitConversion で度になる）。キーの目盛り・再生範囲には含めない |
| アニメーションレイヤー | animBlendNodeAdditiveDL・DA・Rotation（入力 A × ウェイト A + 入力 B × ウェイト B）、animLayer（ウェイト .w とミュート .m を読む） |
| 行列ノード | multMatrix（Maya と同じく i[0] · i[1] · … の順）・decomposeMatrix（回転順 .ro）・composeMatrix（オイラー角・四元数）・inverseMatrix。DAG ノードの行列の属性（worldMatrix・parentMatrix など）も入力にできる |
| 四元数ノード | quatToEuler・eulerToQuat（回転順 .iro）・quatProd（Maya と同じく入力 1 を先に回す）・quatInvert・quatNormalize・quatSlerp |
| expression | 式（.ixp）を解釈して評価する。入力 .I[n]・出力 .O[n]・frame・time・変数（$x。float / int）・代入（= += -= *= /= ++ --）・四則演算と %（整数どうしの割り算は切り捨て）・比較・論理・? :・if / else・for・while・数学関数（sin・cos・tan・sind など度の版・asin・acos・atan・atan2・abs・sqrt・pow・exp・log・floor・ceil・sign・min・max・clamp・smoothstep・linstep・deg_to_rad・rad_to_deg・fmod・hypot など）。フレームごとに最初から評価する。frame・time を使う式があれば、キーがなくてもタイムラインを出す |
| cluster（カーブの変形） | ハンドルの行列（.ma）と bindPreMatrix（.pm）で CV を動かす（Maya の p · gm · pm · ma · gm⁻¹）。CV のウェイト（.wl）とエンベロープで元の位置と混ぜる。クラスタで動くワイヤーにも使える。relative（ハンドルの親の動きを除く）には未対応 |
| wire（カーブの変形） | ワイヤー（.dw）とベースワイヤー（.bw）の差でカーブの CV を動かす（尻尾・胴体のスプライン IK のカーブなど）。ワールド空間で、CV ごとにベースワイヤーの一番近い点を求め、そこでのワイヤーの移動・向きの変化（.rot）・スケール（.sc）を、影響範囲（.dds）による減衰 (1 − (距離/範囲)²)² で掛ける。エンベロープ（.en）と CV のウェイト（.wl）も使う。Maya の計算式は公開されていないため近似（tension・localInfluence・ホルダーは使わない）。メッシュの wire には未対応 |
| そのほか | distanceDimShape（距離の寸法。開始点 .sp と終了点 .ep（ふつうはロケーターの worldPosition）の距離 .dist。伸びる IK などに使う）、curveInfo（カーブの長さ .al。ストレッチの計算などに使う）、pointOnCurveInfo（パラメータ .pr の点 .p・接線 .t・正規化した接線 .nt・法線 .n・.nn・曲率の中心と半径。turnOnPercentage なら .pr は長さの割合）、displayLayer（値を読むだけ） |

- ウェイトはカーブで動かせます（スペースの切り替えなど）。コントローラーの独自の属性（IK/FK の切り替えなど）も、カーブや値をそのまま使います。値が書かれていない独自の属性は、addAttr の既定値（-dv）を使います（キーのあるノードにコンストレイントを付けたときにできる blendPoint1・blendOrient1・blendParent1 など。pairBlend のウェイトになる）。
- 未対応（警告を出し、そこから先はファイルの値）: tangent・normal・geometry などほかのコンストレイント、ikSpringSolver・HumanIK、解釈できない expression（MEL コマンド・getAttr などの呼び出し、文字列、ベクトル、rand などの乱数、.I/.O 以外の属性の参照、フレームをまたいで値を持ち越すグローバル変数）、blendMatrix・pickMatrix・aimMatrix などほかの行列ノード、animBlendNodeAdditiveScale などほかのアニメーションレイヤーのノード、skinCluster・wire・cluster 以外のデフォーマで動くカーブ、メッシュの wire・cluster、プラグインのノード（自作ノード）。どこで止まっているかは「リグの診断」で確認できます。
- 循環（自分の結果を自分で使う接続）に当たったら、そこはファイルの値で打ち切り、警告を出します。
- **値を求められないノードの推定（試作）**: 未対応のノードの影響を受けるノード（その子や、それをターゲットにするコンストレイントで動くノードも含む）は、.ma に値が残っていないため、そのままでは原点に集まります。バインドポーズの情報（skinCluster の .pm・dagPose・ジョイントの .bps）があるノードは、値を求められた一番近い祖先からの相対をバインドポーズのとおりに保って表示します（形を保ったまま、確かな部分の動きについていく）。ジョイントの表示（J）で、推定したノードは薄紫、推定もできないノード（バインドポーズの情報がない）は灰色になり、選択したノードの情報に理由を出します。推定では、そのノードの求められた成分（例: キーのある移動）も使いません。

**Maya 内で読み込む場合**

- Maya が評価した結果を使うので、ヒストリが残っていても、コンストレイントなどで動くノードも、Maya と同じ位置に表示できます。バインドポーズは .pm とジョイントの bindPose 属性から復元します。
- 表示・非表示、選択の可否、カメラ、カメラシーケンサのショット、開いたときのカメラ（作業中のモデルパネルのカメラ）は、Maya の状態から読みます。
- スキン付きメッシュは skinCluster の入力形状を使います。skinCluster より前段のデフォーマ（blendShape など）の効果は形状に含まれますが、後段のものは反映されません。

**テクスチャ（共通）**

- 対象のシェーダーと属性:

  | シェーダー | 読む属性 |
  |---|---|
  | lambert・blinn・phong・phongE・anisotropic | color、normalCamera |
  | aiStandardSurface | baseColor、normalCamera、specularRoughness、metalness、emissionColor、opacity |
  | standardSurface・openPBRSurface | baseColor、normalCamera、specularRoughness、metalness、emissionColor、opacity |
  | StingrayPBS | TEX_color_map、TEX_normal_map、TEX_roughness_map、TEX_metallic_map、TEX_ao_map、TEX_emissive_map |
  | usdPreviewSurface | diffuseColor、normal、roughness、metallic、occlusion、emissiveColor、opacity |

  そのほかのシェーダーでは color・baseColor などの名前でベースカラーを探します。
- file ノードの出力のどれをつないでいるかを見て、チャンネルを選びます（例: ORM の outColorG をラフネスに、outColorB をメタリックに）。画像全体（outColor）を 1 チャンネルのマップにつないでいる場合は R を使います。
- ノーマルマップは、file ノードが直接つながっている場合（StingrayPBS など）と、bump2d（使い方が「Tangent Space Normals」）・aiNormalMap を経由する場合に対応します。高さのバンプ（bump2d の「Bump」）は未対応です。接線は画面上で求めるため、Maya と細部の陰影が少し違うことがあります。緑の向きは OpenGL 形式（Maya と同じ）が既定で、［マップ］で DirectX 形式に切り替えられます。
- AO は、three.js の仕様で環境光（空と地面の光）の部分だけを暗くします。
- 色の属性に file ノードが**直接**つながっている場合だけ表示します（layeredTexture などを挟む場合は警告を出し、マテリアルの色で表示します）。テクスチャがないマテリアルは、Maya のマテリアルの色で表示します。
- 対応形式: TGA（RLE 圧縮・アルファあり・左下／左上始まりのいずれも可）、PNG、JPEG、BMP、GIF、WebP。TIFF・PSD・EXR・.tx などは表示できません（警告を出します）。長辺が 2048px を超える画像は表示用に縮小します。
- パスの検索順:
  1. 書かれているパスそのもの（相対パスなら、プロジェクトのルート → .ma のフォルダを基準）。Maya 内では、Maya が解決したパスを最優先にします。
  2. Maya プロジェクト（.ma の上位フォルダに workspace.mel がある）なら、sourceimages フォルダ
  3. .ma と同じフォルダ
  4. .ma と同じフォルダにあるフォルダの中（4 階層下まで。ファイル名で探し、大文字・小文字は区別しない）

  2・3 では、まずファイル名だけで探し、見つからなければ元のパスの親フォルダ名を 1 つずつ足して探します（例: `a.tga` → `tex/a.tga` → `chr/tex/a.tga`）。4 で同じ名前のファイルが複数見つかった場合は、シーンのファイル名に名前が近いフォルダのものを選び（例: `chr_a.ma` なら `chr_a_textures/` を `chr_b/` より優先）、どれを選んだかを警告に出します。見つからなかった場合は、試したパスの一覧を警告に出します。環境変数（`$VAR`）は展開します。
- UDIM: パスに `<UDIM>` を含む場合と、fileノードのタイル指定（UV タイリングモード = UDIM）でファイル名にタイル番号が入っている場合に対応します。上と同じ順にフォルダを探し、タイルの画像がそろっている最初のフォルダを使います。面ごとに UV の平均位置からタイルを判定して、そのタイルの画像を貼ります。`<UVTILE>` 形式は未対応です。
- 透過: 既定では、Maya でアルベドと同じ file ノードのアルファ（outTransparency / outAlpha）が不透明度・透明度（transparency・opacity など）につながっているマテリアルだけ、アルファで透過します。ツールバーの［マップ］で「アルファのある画像すべて」「透過しない」に切り替えられます。方式は「切り抜き」（アルファ 0.5 未満を描かない）と「半透明」から選べます。
- UV セット: テクスチャに紐づいた UV セット（.ma では uvChooser、Maya 内では uvLink）を使い、なければ現在の UV セットを使います。place2dTexture の繰り返しやオフセットは反映しません。
- UV の継ぎ目では表示用に頂点を分けますが、ウェイト表示・頂点のクリック・頂点番号は元の頂点のまま扱います。
- 面ごとのマテリアルの割り当ては、メッシュの面リスト（`.iog[0].og[k].gcl`）から読みます。デフォーマ（skinCluster など）を持つメッシュでは、Maya が面リストをデフォーマ経路上の groupParts（`.ic`）に書くので、groupId をたどってそこから読みます。どちらにも見つからない場合は警告を出し、その面は既定のマテリアルで表示します。
- 現在の UV セットに面との対応（UV の割り当て）がない場合は、対応のある UV セットを使います（警告を出します）。元形状に UV がなければ、変形後シェイプの UV を使います。
- **テクスチャが貼られないとき**: 左の［メッシュ］タブで、メッシュごとの UV セット・UV のない面の数・マテリアルごとの面数・テクスチャの状態を確認できます。同じ内容は `python -m ma_viewer info scene.ma` でも表示できます。
- ウェイト表示中は、ヒートマップを見やすくするためテクスチャを外します。

**変形表示（共通）**

- ウェイトは、変形時に常に正規化します（合計で割って合計 1 にする）。頂点のウェイト一覧には、保存値と変形に使う値（→ の右）を表示します。
- ウェイトの合計が 0 の頂点は、skinCluster の「ウェイトの分配」の設定に合わせて割り当てます。
  - 距離（既定）: その頂点に記録されているジョイント（値 0）に、バインド時の距離が近いほど多く配分します（1 つなら 100%、等距離の 2 つなら 50% ずつ）。記録が 1 つもなければ、いちばん近いジョイントに 100% 割り当てます。
  - 近傍: 辺でつながった頂点のウェイトの平均を使います（記録されているジョイントがあれば、その中で配分）。
  - Maya のドキュメントには、分配の正確な計算式は書かれていないため、近似です。割り当てた頂点は、警告と頂点のウェイト一覧で分かるようにしています。
- 1 頂点あたり 8 インフルエンスまで、Maya と同じ式で変形します。three.js 標準のスキン処理は 4 つまでのため、シェーダーを差し替えて拡張しています（`web_src/src/skinning8.js`）。9 つ以上ある頂点は上位 8 つに絞り、合計値を保つよう配分し直します。ヒートマップと数値は全インフルエンスで表示します。
- スキニング方式はリニアのみです。デュアルクォータニオンの場合は警告を出します。

### ビューア（JS）の変更

## トラブルシューティング

- **「WebGL を初期化できませんでした」と表示される**: GPU ドライバを更新してください。スタンドアロン版は起動時に `--ignore-gpu-blocklist` を指定しています。環境変数 `QTWEBENGINE_CHROMIUM_FLAGS` を自分で設定している場合は、そちらが優先されます。
- **Maya で「QtWebEngine が含まれていません」と出る**: Maya のスクリプトエディタで `from PySide6 import QtWebEngineWidgets` を実行して確認してください。使えない場合は、`python -m ma_viewer export` で JSON に変換し、スタンドアロン版またはブラウザで開いてください。
- **メッシュが表示されない**: ログの警告を確認してください。多くの場合、ヒストリが残っていて形状データがファイルにありません。
- **スキン変形の表示が Maya と違う気がする**: F12 で開発者ツールを開き、コンソールで `window.mayaViewer.debug.checkSkinning(0)`（0 はメッシュの番号）を実行してください。GPU の変形と、Maya の式による計算を描画結果で比べ、不一致の画素の割合（`ratio`）を返します。0 に近ければ、ビューア内の計算は一致しています。その場合の違いは、データ（ウェイトやバインド行列）か、反映していないデフォーマによるものです。
- **ジョイントが小さすぎる／大きすぎる**: ツールバーの［表示］メニューのスライダーで大きさを変えられます。基準の大きさは、骨の長さの中央値から決めています。
