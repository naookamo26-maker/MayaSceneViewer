# 対応範囲と制限

このページは [README](../README.md) から分けたものです。


**.ma から読み込む場合**

- **ヒストリは削除して保存してください。** polyCube などの作成ノードから形状が作られているメッシュは、頂点データがファイルにないため表示できません（警告を出して除外します）。
- スキン付きメッシュは、変形後シェイプから groupParts・tweak を経由して元形状（〜Orig）までさかのぼって特定します。tweak の頂点オフセットも反映します。
- 頂点法線は、ハードエッジで分け、Maya の頂点法線の重み（.vnm。既定は角度と面積）で隣の面の法線を合わせて計算します。ユーザーが指定した法線（ロックした法線）・スムーズメッシュプレビュー（3 キー）・頂点カラーは使いません（前の 2 つは警告を出します）。
- skinCluster 以外のデフォーマ（blendShape、deltaMush など）の効果は反映しません（警告を出します）。
- 対象外のもの: インスタンス（`parent -add`）、Maya バイナリ（.mb。リファレンス先が .mb の場合も読み込みません）。
- **リファレンス**: 読み込みの状態は、ファイルの先頭の `file -rdi` の行（`-dr 1` ならアンロード）で決めます。親のシーンの指定を、内側のファイルの指定より優先します。リファレンスの編集は、内側のファイルのものから順に当てます。編集に書かれたパスのノードがない場合（保存したあとに、リファレンスの元のファイルで階層を変えたときなど）は、同じ名前のノードが 1 つだけならそれに当てます（警告を出します）。それでも相手が見つからない編集は使わず、見つからないノードの名前をリグの診断（`python -m ma_viewer rig`）の「リファレンスの編集で相手のノードが見つからないもの」に出します。編集のうち、ロック（lockNode）・属性の削除・名前の変更などは反映しません。リファレンスの中の起動時のカメラ（persp など）・保存時のフレーム・再生範囲・単位・upAxis は使わず、シーン（開いたファイル）のものを使います。リファレンスの作業単位がシーンと違う場合は、値を換算せずに使います（警告を出します）。テクスチャは、シーンの探し方に加えて、リファレンスのファイルのプロジェクト（sourceimages）とフォルダも探します。
- 属性名は、標準のノードの長い名前（`multiplyDivide1.input1X` など。スクリプトで作ったリグで多い）でも短い名前でも読めます。ノードの型ごとの名前の表（`ma_viewer/attr_names.json`。Autodesk の技術資料から作ったもの）で短い名前にそろえます。
- 作業単位は cm だけに対応しています。cm 以外の単位では、移動の値と行列・頂点の値の単位が合わないため形が崩れます（警告を出します。Maya で作業単位を cm にして保存し直してください）。単位（長さ・角度・時間）がシーンと違うリファレンスにも警告を出します。角度は度・ラジアンのどちらにも対応します。
- 穴付きの面は、穴を無視して表示します。
- **接続で値が決まる属性**は、.ma に値が残っていません。アニメーションカーブと、下の「リグ」で評価できるものは、アニメーションを読み込むと評価した値で表示します。それ以外（エクスプレッションなど）で決まるノードは、バインドポーズの情報があれば「ファイルの値」でもその姿勢で表示し、なければ既定値（移動 0・回転 0）で表示します。どちらの場合も警告を出し、選択情報に接続元を表示します。移動・回転・スケールの接続元が 1 つでも評価できないと、そのノードはまとめてこの扱いになります（コンストレイントで動く移動に、評価できない回転の接続が混ざっている場合など）。警告には評価できない接続を先に出し、評価できる接続（コンストレイントなど）は文末に添えます。ターゲット（.tg）がつながっていないコンストレイントは、そのことも出します。
- **ディスプレイレイヤー**: 非表示のレイヤー（.v が off）に入っているノードは、非表示で読み込みます（レイヤーが無効なら影響しません）。レイヤーの表示（.v）・有効（.e）が接続で決まる場合は、入っているノードの表示としてフレームごとに評価します（ほかのレイヤーの属性の接続は評価しません）。
- **接続で決まる表示（visibility）**: .ma に値が残らないため、アニメーションを読み込むまで（または［アニメーションを読み込む］がオフのとき）は表示のままです。読み込むと、カーブと下の「リグ」で評価できるノードから求めた値で表示します。評価できないノード（エクスプレッションの一部など）を経由する場合は、ファイルの値のまま表示します。
- **選択の可否**: テンプレート（.template）と、描画のオーバーライドかディスプレイレイヤーの表示の種類（テンプレート・リファレンス）から決めます。transform は、自分と祖先の設定に加えて、シェイプ（メッシュ・カーブ・カメラ以外。ロケーター・自作の DAG ノードなど）がすべて選べない設定なら選べないとします。選択マスク・選択の優先度・ロックしたノードなど、ほかの選択の設定は見ません。
- **カメラ**: 再現するのはカメラの視点と投影です。被写界深度・オーバースキャン・パンとズーム（2D パン）・イメージプレーン・カメラの注視点（camera and aim の aim）・ステレオカメラの左右のずれは反映しません。カメラの属性のうち、接続・キーで値が決まるもの（焦点距離など）は、アニメーションを読み込むと評価します。
- **カメラシーケンサ**: ショット（shot）のシーンの範囲・シーケンス上の開始・scale・preHold・postHold・トラック・ミュート・カメラを読みます。シーケンス上の終わりは、開始 + preHold + (終了 − 開始) × scale + postHold で求めます。Maya は既定値と同じ値を .ma に書かないため、書かれていない値は既定値（開始・終了・シーケンス上の開始は 0、トラックは 1）とします。オーディオ・クリップ（映像）・トランジション・ショットごとの解像度は使いません。
- **開いたときのカメラ**: 画面構成のスクリプト（uiConfigurationScriptNode）の「Current Layout」で最初のビューのカメラを使います。複数画面のレイアウトでは、どのビューで作業していたかは分からないため、最初のビューになります。
- **Trax・カメラシーケンサの .ma の書式**: 実際の Maya のファイルでの確認ができていないため、Autodesk のドキュメントから推定した書式で作ったサンプルで確認しています（属性は短い名前・長い名前のどちらでも読みます）。
- **offsetParentMatrix**（Maya 2020 以降）は、ファイルの値をローカル行列のあとに掛けます（ワールド行列 = ローカル · offsetParentMatrix · 親）。接続で決まる場合は、アニメーションを読み込むと評価した値を使います。
- **ローカル行列のそのほかの属性**: 回転・スケールのピボット（rotatePivot・scalePivot とその補正 rpt・spt）、rotateAxis、jointOrient、せん断（shear）、回転順（rotateOrder）も、接続やカーブで決まる場合は毎フレーム評価します（足のピボットの切り替え・スペースの切り替えなど。ジョイントは Maya と同じくピボット・せん断を使いません）。
- **移動・回転・スケールの制限**（transform・joint の minTransLimit / maxRotLimit などと、その有効化のフラグ）は、有効なものだけ、ファイルの値・カーブ・接続・IK で決まった値をその範囲に収めます。IK のソルバーは制限を考えずに解き、結果を制限で止めます。

**アニメーション（.ma から読み込む場合）**

- 再生するのは、表示するノード（メッシュ・ジョイント・インフルエンスとその親）の移動・回転・スケールです。値は、アニメーションカーブ（animCurveTL・TA・TU）と、下の「リグ」で評価できるノードから求めます。
- 移動・回転・スケールのほかに、表示（.v・.lodv・.ovv）と、カメラの属性（焦点距離・フィルムバック・クリップ面など）のカーブ・接続も評価します。
- **キャラクターセット**（character）も再生します。カーブがキャラクターセットの属性に直接つながる場合はその値を、Trax のクリップ（clipLibrary・clipScheduler・animClip）の場合は、各クリップの開始・ソースの範囲・スケール・前後のサイクル・hold・ウェイト・有効・トラックを読んで、そのフレームで有効なクリップの値を使います。クリップが重なるときは、あとから始まるクリップ（同じならトラックの番号が大きい方）を使い、クリップのない区間は直前のクリップの最後の値を保ちます。クリップ間のブレンド・相対（relative）クリップのオフセット・タイムワープは反映しません。
- 再生しないもの（警告を出します）: 下の「リグ」で評価できないノード（解釈できない expression・未対応のコンストレイントやノード・プラグインのノードなど）を経由する値。移動・回転・スケール・表示・カメラ・テクスチャの UV の繰り返しとオフセット以外の属性（マテリアルの色など）のカーブ。
- 補間: 重みなしのカーブはエルミート補間、重み付きのカーブは 3 次ベジエで、Autodesk の animX（Maya と同じ評価をする公開ライブラリ）と同じ計算です（接線が区間より長いときの直し方・範囲外の扱いを含む）。接線の種類のうち、リニア・フラット・ステップ・ステップ（次）・固定（kix などの値）・オート・オートミックス・オートイーズも animX と同じです。オートカスタムはオートイーズとして扱います。スプライン・クランプ・プラトーは Maya の計算が公開されていないため近似です（プラトーは山・谷で平らにし、キーの値を行き過ぎないようにします）。スロー・ファストはスプラインとして扱います。回転の補間（rotationInterpolation の同期したオイラー・クォータニオン）には対応せず、X・Y・Z を別々に補間します。調査の詳細と、Maya で評価した値と比べる手順は [docs/animation_curves.md](animation_curves.md)。
- 範囲外（pre / post infinity）: 一定・リニア・繰り返し・オフセット付き繰り返し・往復に対応します。
- 時間の単位（currentUnit -t。film・ntsc・pal・game・show・palf・ntscf と「○○fps」）と、再生範囲（sceneConfigurationScriptNode の playbackOptions）を読みます。再生範囲がなければ、キーのある範囲を使います。読み込み直後のフレームは、保存したときの現在のフレーム（time1）です。
- 再生は実時間です。描画が間に合わないときはフレームを飛ばします。
- アニメーションを読み込んでいる間（2 段階目）と、［アニメーションを読み込む］がオフのときは、リグで決まる表示・カメラの焦点距離などは評価しません。

**リグ（.ma から読み込む場合）**

表示するノードの移動・回転・スケールの接続を上流へたどり、評価に必要なノードを洗い出します（1 段階目。接続だけを見るので軽い処理です）。コントローラーなどの DAG ノードは階層にも表示します。属性の値は 2 段階目で読み、評価はビューアで行います（`web_src/src/rig.js`）。Maya と同じ考え方の近似で、細部は Maya と違うことがあります。

| 種類 | 内容 |
|---|---|
| コンストレイント共通 | 動かされるノードの親の空間（.parentMatrix = 親のワールド行列 · offsetParentMatrix）で値を決める。Maya のコンストレイントは rotateAxis の入力を持たないので、ターゲット・動かされる側とも rotateAxis を使わない。ターゲットのウェイトがすべて 0 のときは、enableRestPosition（.erp）が有効ならレストの値（.rst・.rsrr・.rs。成分の短い名前は .rtx・.rrx・.rsx など（「rst + 軸」ではない）で、成分で書かれた値・成分への接続も読む。.rsrr は角度の属性なので、接続の値はラジアンのまま使う）。回転の値は Maya と同じ選び方（2 通りの角度のうち 0 に近い方。parentConstraint は前回の値 .lr に近い方。Maya が保存した実物のリグで確かめた） |
| pointConstraint | ターゲットの回転ピボットの重み付き平均 + オフセット（.o）。ターゲットの位置は Maya と同じく (translate + rotatePivot + rotatePivotTranslate) · 親の空間（scalePivot・スケールによらない） |
| orientConstraint | ターゲットの向き（親の空間 · jointOrient · rotate）の重み付き平均（四元数）· オフセット（.o）。scaleCompensate（.ssc）が有効なら、動かされるジョイントの親のスケールの打ち消し（.is）を親の空間に入れる。補間の種類（.int）は Average と、2 ターゲットの Shortest（最短の弧の slerp）に対応（No Flip・Longest・Cache と 3 ターゲット以上の Shortest は平均として評価し、警告を出す。parentConstraint も同じ） |
| parentConstraint | ターゲットごとに（ターゲット · オフセットの移動 · オフセットの回転）を求め、位置と向きを重み付き平均。ターゲットの空間の原点は、ターゲットの回転ピボット（Maya と同じ。cluster のハンドルのようにピボットが原点から離れたターゲットでは、動かされるノードの回転ピボットがターゲットの回転ピボットに付く） |
| scaleConstraint | ターゲットのワールドのスケールの加重幾何平均（Maya の資料のとおり）÷ 親の空間のスケール × オフセット（.o） |
| poleVectorConstraint | ターゲットの位置 − 開始の位置（IK ハンドルの極ベクトル）。Maya と同じく、開始の位置はコンストレイントの属性 (constraintRotatePivot + constraintRotateTranslate) を pivotSpace でワールドへ移したもの（ふつうは開始ジョイントの位置。crp がつながっていなければ親の原点などになる）、ターゲットの位置は (targetTranslate + targetRotatePivot + targetRotateTranslate) を targetParentMatrix で移したもの |
| lookAt（カメラとエイム） | Maya の［カメラとエイム］・［カメラ、エイム、アップ］のグループ。aimConstraint と同じ解き方（aim の既定はカメラの −Z）に、world up がシーンの上・ベクトルのときは twist（.tws）で視線のまわりに回す（ロール。正の値は、カメラからターゲットへの向きのまわりに左ねじの向き。Maya と見比べて確認済み）。twist はキー・別のノードの属性・カメラのシェイプの独自の属性からつないでもよい（独自の角度の属性 doubleAngle の値はラジアンに直して読む）。twist・オフセット・up などの補助の入力が未対応のノードにつながっているときは、その接続だけを外してファイルの値で評価する（エイムの向きは求め、警告を出す）。lookAt のグループ自身がキー・コンストレイント（別のノードへのポイント・オリエントコンストレイントなど）・計算ノードで動くときは、ふつうの transform と同じくその値で動かす（グループはコンストレイントであり、カメラ・エイムの親の transform でもある） |
| aimConstraint | aim ベクトル（.a）をターゲットへ向け、up ベクトル（.u）を world up の側に向ける。world up はシーンの上・オブジェクト（.wum の位置）・オブジェクトの回転・ベクトル（.wu）・なし。world up がなしのときと、aim と up が平行なとき（ひねりが決まらない）は、Maya と同じく親の空間で回転 0 の向き（jointOrient を含む）から測る最短の回転。オフセット（.o）。scaleCompensate は orientConstraint と同じ |
| IK（ikRPsolver） | 1 ボーン（ジョイント 2 つ。まぶたなどで多い）は、終端がハンドルの方を向くよう開始ジョイントを最短の回転で回す（Maya が保存した回転で確かめた）。2 ボーン（開始・中間・終端のジョイント）は、ハンドルに届くように余弦定理で曲げ、極ベクトル（ハンドルの親の空間。ファイルに値がなければ Maya の既定値 (0, 0, 1)）の側に肘を置き、ひねり（twist）で回す。届かないときはまっすぐ伸ばす。ikBlend で FK と混ぜる。まっすぐなチェーンは優先角（.pa）で曲げる向きを決める。3 ボーン以上は、FK の形を極ベクトルの面に合わせて回してから、面の上で FABRIK（反復の解き方）で解く（曲がり方の配分は Maya と違うことがある）。ツールバーの［表示］→「IK の解き方（3 ボーン以上）」で「優先角から曲げる」に切り替えると、FK の値によらず優先角（.pa。ファイルになければ 0）の形から、関節ごとの曲がりの比を保ったまま曲がり具合だけを変えてハンドルに届かせ、極ベクトル（＋ひねり）の側へ向ける（Maya との一致を比べるための試しの解き方。次回の起動でも使う）。ジョイントの jointType（回転の軸の制限）・stiffness・回転の制限の減衰は使わない（IK のチェーンにあれば警告を出す。ikSCsolver も同じ） |

  - **コントロールリグの FK**（近似）: FK のコントローラー（hikFKJoint）で動くスケルトンの部位は、HIKState2SK の代わりに multMatrix → decomposeMatrix の組を作って評価します（キー・ポーズ確認でコントローラーを動かすと、スケルトンが追従します）。部位のワールドの行列は (スタンスのスケルトンの向き · スタンスのコントローラーの向き⁻¹) · コントローラーのワールドの行列（行ベクトル）、ジョイントの値はこれを parentInverseMatrix でローカルにして、移動はそのまま、回転は rotateAxis と jointOrient を除いて回転順で分けたものです。スタンスのスケルトンの向きはキャラクターの <部位>Rx〜Rz（xyz の順。<部位>JointOrient は掛けない）、スタンスのコントローラーの向きは、コントローラーの回転の値を 0 にした向きです（実物のコントロールリグのシーンで、スタンスのスケルトン = バインドポーズ、コントローラーの回転の値 = 0 であることを全部位で確かめた）。スケールは使いません。IK エフェクター（Reach が 0 でないもの・キーのあるものは警告とリグの診断に出す）・ピン留め・床の接地・Pull・Stiffness などの全身の解き方は再現しません（Reach が 0 なら HumanIK は FK の姿勢をそのまま使うため、その場合は Maya に近い結果になる見込みですが、Maya の結果と比べての確認はまだしていません）。FK のコントローラーのない部位は評価しません。
  - **リターゲット**（近似）: 別のキャラクターのスケルトン（HIKSK2State → HIKRetargeterNode）で動く部位も、行列ノードに組み立てて評価します。部位のワールドの向きは 回転(ターゲットのスタンス · ソースのスタンス⁻¹) · ソースの部位の今のワールド · Dₛ⁻¹ · Dₜ（D = 基準（Reference の部位）のスタンス⁻¹ · 基準の今のワールド。基準がスタンスから動いた分）で、ソースの部位がワールドで回った分だけ、ターゲットの部位もワールドで回ります（基準がスタンスで回っているキャラクターでも、動きの軸はずれません）。腰（Hips）の位置は、ソースの腰のスタンスからの動きを、腰の高さの比（ターゲット ÷ ソース。基準からの距離）で縮めてターゲットのスタンスの位置に足します。ほかの部位の位置はターゲットのスタンスのローカル（骨の長さはターゲットのまま）、ソースにない部位（指など）はスタンスの形で親についていきます。ソースのスケルトンがコントロールリグや別のリターゲットで動いていても、その結果を使います。HumanIK のリターゲットの設定（ソースの一致・Reach・床の接地・オフセットなど）は再現しません（Maya の結果と比べての確認はまだしていません）。
  - **スタンス**: ソースのない HIKSolverNode で動くスケルトンは、スタンス（キャラクタライズの姿勢）· Dₜ で表示します（キャラクタライズのあとで基準を動かしたキャラクターも、基準についていきます）。
  - そのほか（キャラクターの分からない HIKState2SK など）で動くスケルトンは評価しません。警告をキャラクターごとに 1 つにまとめ（ジョイントごとの「接続で決まる」の警告は出しません）、HumanIK で動くジョイントは、バインドポーズの情報があればその形で表示します。Maya と同じ動きにするには、Maya でスケルトンにベイクしてください（HumanIK のパネルの［ベイク処理］→［スケルトンのベイク処理］）。部位があるかは、キャラクタライズ（ジョイントの .ch の接続）で決めます（HumanIK は 0 の値を書かないため、スタンスの値のない部位は 0）。
  - リグの診断の「HumanIK」に、部位の割り当て・ソース・FK・リターゲット・スタンスで求める部位・動くノードを出します。HumanIK の型（requires -nodeType に mayaHIK の型と書かれていても）は Maya の標準の型として扱い、自作ノードの割り当ての雛形は出しません。コントロールリグの FK のコントローラー（hikFKJoint）はジョイントとして読みます。
- 循環（自分の結果を自分で使う接続）に当たったら、そこはファイルの値で打ち切り、警告を出します。
- **値を求められないノードの推定（試作）**: 未対応のノードの影響を受けるノード（その子や、それをターゲットにするコンストレイントで動くノードも含む）は、.ma に値が残っていないため、そのままでは原点に集まります。バインドポーズの情報（skinCluster の .pm・dagPose・ジョイントの .bps）があるノードは、値を求められた一番近い祖先からの相対をバインドポーズのとおりに保って表示します（形を保ったまま、確かな部分の動きについていく）。ジョイントの表示（J）で、推定したノードは薄紫、推定もできないノード（バインドポーズの情報がない）は灰色になり、選択したノードの情報に理由を出します。推定では、そのノードの求められた成分（例: キーのある移動）も使いません。

**Maya 内で読み込む場合**

- スタンドアロンで .ma を開いたときと同じ扱いです。Maya のメモリの上のノード・属性・接続を、Maya が .ma に書くのと同じ文（独自の属性は `MFnAttribute.getAddAttrCmd`、値は `MPlug.getSetAttrCmds`）にして .ma の読み込みに通し、そのあとの変換（アニメーション・リグ・カーブ・マテリアル・警告・リグの診断）は同じコードで行います。ファイルは書き出しません（保存していない変更もそのまま読みます）。.ma と同じく、変形の入力（ヒストリ・skinCluster など）のあるカーブの形は書かず、入力から求めます（リグで動くスプライン IK のカーブなど）。
- メッシュの形・UV とスキンウェイト（.ma の大部分を占めるデータ）は文にせず、Maya の API から配列のまま入れます（大きなシーンでも、組み立てる文は .ma よりずっと小さくなります）。ヒストリの残っているメッシュ（polyCube などから作られ、.ma には形がないもの）も、Maya が評価した形で表示します。
- リファレンスは、Maya が読み込んだノードをそのまま使います。.mb のリファレンスや、パスが見つからないリファレンス（Maya が読めているもの）も表示できます。Maya でアンロードしているリファレンスは表示しません（警告に出します）。
- 現在のフレーム・再生範囲・開いたときのカメラ（作業中のモデルパネルのカメラ）・テクスチャを探すプロジェクトは、いまの Maya の状態を使います。
- Maya の画面を止めるのは、ノードを集めるあいだだけです。変換とアニメーションの読み込みは、.ma と同じく読み込みのスレッドで行います（変換結果のキャッシュは使いません）。
- インスタンス（同じシェイプを複数の親の下に置いたもの）は、.ma と同じく最初の 1 つだけを表示します。

**テクスチャ（共通）**

- 対象のシェーダーと属性:

  | シェーダー | 読む属性 |
  |---|---|
  | lambert・blinn・phong・phongE・anisotropic | color、normalCamera |
  | aiStandardSurface | baseColor、normalCamera、specularRoughness、metalness、emissionColor、opacity |
  | standardSurface・openPBRSurface | baseColor、normalCamera、specularRoughness、metalness、emissionColor、opacity |
  | StingrayPBS | TEX_color_map、TEX_normal_map、TEX_roughness_map、TEX_metallic_map、TEX_ao_map、TEX_emissive_map |
  | usdPreviewSurface | diffuseColor、normal、roughness、metallic、occlusion、emissiveColor、opacity |
  | layeredShader | 表示する層（下記）につながったシェーダーの属性。層の色に file ノードが直接つながっていればそれ、何もなければ層の色の値 |

  そのほかのシェーダーでは color・baseColor などの名前でベースカラーを探します。
- **層を重ねるノード**（layeredShader・layeredTexture）: ビューアは層を重ねて描けないので、上（層 0）から見て最初の不透明な層を表示します（その下の層は Maya でも見えません）。layeredShader は透明度 0（つながったシェーダーの透明度を見る。Hypershade でつなぐと outTransparency もつながるため）、layeredTexture はアルファ 1 で重ね方が None・Over なら不透明とし、非表示（isVisible オフ）・完全に透明な層は数えません。それより上に見える層（半透明・file のアルファなどのマスク付き・Add などの重ね方）があれば、表示しない層として警告します。不透明な層がなければいちばん下の層を表示します。
- file ノードの出力のどれをつないでいるかを見て、チャンネルを選びます（例: ORM の outColorG をラフネスに、outColorB をメタリックに）。画像全体（outColor）を 1 チャンネルのマップにつないでいる場合は R を使います。
- ノーマルマップは、file ノードが直接つながっている場合（StingrayPBS など）と、bump2d（使い方が「Tangent Space Normals」）・aiNormalMap を経由する場合に対応します。高さのバンプ（bump2d の「Bump」）は未対応です。接線は画面上で求めるため、Maya と細部の陰影が少し違うことがあります。緑の向きは OpenGL 形式（Maya と同じ）が既定で、［マップ］で DirectX 形式に切り替えられます。
- AO は、three.js の仕様で環境光（空と地面の光）の部分だけを暗くします。
- 色の属性に file ノードが直接（または layeredTexture を経由して）つながっている場合に表示します（ほかのノードを挟む場合は警告を出し、マテリアルの色で表示します）。テクスチャがないマテリアルは、Maya のマテリアルの色で表示します。
- 対応形式: TGA（RLE 圧縮・アルファあり・左下／左上始まりのいずれも可）、PNG、JPEG、BMP、GIF、WebP。TIFF・PSD・EXR・.tx などは表示できません（警告を出します）。長辺が 2048px を超える画像は表示用に縮小します。
- パスの検索順:
  1. 書かれているパスそのもの（相対パスなら、プロジェクトのルート → .ma のフォルダを基準。Maya 内では、いま設定しているプロジェクトのルート）
  2. Maya プロジェクト（.ma の上位フォルダに workspace.mel がある）なら、sourceimages フォルダ
  3. .ma と同じフォルダ
  4. .ma と同じフォルダにあるフォルダの中（4 階層下まで。ファイル名で探し、大文字・小文字は区別しない）

  2・3 では、まずファイル名だけで探し、見つからなければ元のパスの親フォルダ名を 1 つずつ足して探します（例: `a.tga` → `tex/a.tga` → `chr/tex/a.tga`）。4 で同じ名前のファイルが複数見つかった場合は、シーンのファイル名に名前が近いフォルダのものを選び（例: `chr_a.ma` なら `chr_a_textures/` を `chr_b/` より優先）、どれを選んだかを警告に出します。見つからなかった場合は、試したパスの一覧を警告に出します。環境変数（`$VAR`）は展開します。
- UDIM: パスに `<UDIM>` を含む場合と、fileノードのタイル指定（UV タイリングモード = UDIM）でファイル名にタイル番号が入っている場合に対応します。上と同じ順にフォルダを探し、タイルの画像がそろっている最初のフォルダを使います。面ごとに UV の平均位置からタイルを判定して、そのタイルの画像を貼ります。`<UVTILE>` 形式は未対応です。
- 透過: 既定では、Maya でアルベドと同じ file ノードのアルファ（outTransparency / outAlpha）が不透明度・透明度（transparency・opacity など）につながっているマテリアルだけ、アルファで透過します。ツールバーの［マップ］で「アルファのある画像すべて」「透過しない」に切り替えられます。方式は「切り抜き」（アルファ 0.5 未満を描かない）と「半透明」から選べます。
- UV セット: テクスチャに紐づいた UV セット（uvChooser）を使い、なければ現在の UV セットを使います。place2dTexture の繰り返し（repeatUV）とオフセット（offset）は反映します。キー・ジョイント・計算ノード・exprespy などの接続で動く値も、フレームごとに反映します（テクスチャを骨で動かすリグなど）。rotateUV・フレームの移動と回転・coverage・ミラー・stagger・wrap のオフ・noiseUV と、UDIM のテクスチャの繰り返し・オフセットは反映しません（警告を出します）。
- UV の継ぎ目では表示用に頂点を分けますが、ウェイト表示・頂点のクリック・頂点番号は元の頂点のまま扱います。
- 面ごとのマテリアルの割り当ては、メッシュの面リスト（`.iog[0].og[k].gcl`）から読みます。デフォーマ（skinCluster など）を持つメッシュでは、Maya が面リストをデフォーマ経路上の groupParts（`.ic`）に書くので、groupId をたどってそこから読みます。どちらにも見つからない場合は警告を出し、その面は既定のマテリアルで表示します。
- 現在の UV セットに面との対応（UV の割り当て）がない場合は、対応のある UV セットを使います（警告を出します）。元形状に UV がなければ、変形後シェイプの UV を使います。
- **テクスチャが貼られないとき**: メッシュを選ぶと（階層のメッシュの行・ビューポートのクリック）、右パネルの［選択］で、UV セット・UV のない面の数・マテリアルごとの面数・テクスチャの状態を確認できます。同じ内容は `python -m ma_viewer info scene.ma` でも表示できます。
- ウェイト表示中は、ヒートマップを見やすくするためテクスチャを外します。

**変形表示（共通）**

- ウェイトは、変形時に常に正規化します（合計で割って合計 1 にする）。頂点のウェイト一覧には、保存値と変形に使う値（→ の右）を表示します。
- ウェイトの合計が 0 の頂点は、skinCluster の「ウェイトの分配」の設定に合わせて割り当てます。
  - 距離（既定）: その頂点に記録されているジョイント（値 0）に、バインド時の距離が近いほど多く配分します（1 つなら 100%、等距離の 2 つなら 50% ずつ）。記録が 1 つもなければ、いちばん近いジョイントに 100% 割り当てます。
  - 近傍: 辺でつながった頂点のウェイトの平均を使います（記録されているジョイントがあれば、その中で配分）。
  - Maya のドキュメントには、分配の正確な計算式は書かれていないため、近似です。割り当てた頂点は、警告と頂点のウェイト一覧で分かるようにしています。
- 1 頂点あたり 8 インフルエンスまで、Maya と同じ式で変形します。three.js 標準のスキン処理は 4 つまでのため、シェーダーを差し替えて拡張しています（`web_src/src/skinning8.js`）。9 つ以上ある頂点は上位 8 つに絞り、合計値を保つよう配分し直します。ヒートマップと数値は全インフルエンスで表示します。
- スキニング方式はリニアのみです。デュアルクォータニオンの場合は警告を出します。
