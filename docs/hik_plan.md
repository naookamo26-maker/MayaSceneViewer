# HumanIK の対応を広げる計画（1.40.1 の時点）

HumanIK（mayaHIK）で動くスケルトンを、いまより Maya に近い動きで再生するための計画です。
この文書を書いた時点では、コードを変更していません。いまの対応範囲は [support_and_limits.md](support_and_limits.md) の「HumanIK」です。

前提は [maintenance_plan.md](maintenance_plan.md) の「0. 前提」と同じです（Viewer としてだけ使う・.mb は解析しない・
cm だけ・Maya の動作を推測で変えない）。

## 0. 方針

- HumanIK のソルバーは計算式が公開されていないので、**ソルバーそのものの再現は目指しません**。
  目に見える差の大きいところを、近似で 1 つずつ埋めます。
- この計画の「Maya の動き」の説明は、HumanIK の一般的な知識によるもので、**Maya で実測していません**。
  「推測で変えない」の前提に合わせ、どの作業も **A0（Maya の結果との比較）で確かめてから実装** します。
  実測と合わなかった作業は、実装しないか、式を直してから実装します。
- 検証用の切り替え（メニュー・設定）は足しません（1.38.0 で廃止した方針のまま）。式は実測で 1 つに決めます。

### いまの状態と、残っている差

| 経路 | いまの扱い | 残っている差 |
|---|---|---|
| コントロールリグの FK | FK のコントローラーのワールドの行列から求める | Reach が 0 なら同じになるはず（Maya との比較は未確認） |
| コントロールリグの IK エフェクター | 無視して FK の姿勢（警告だけ） | キーの間で手足の先がずれる（足の滑りなど） |
| リターゲット | 向きの差を移し、腰の位置だけ高さの比で縮める | 体格の違うキャラクターで足が浮く・滑る |
| ロール骨・ひねりの分配 | 読んでいない（FK のコントローラーのない部位は評価しない） | 前腕・上腕・脚のひねりが 1 つのジョイントに集まる |
| 床の接地 | 読んでいない | 足が床にもぐる |
| Pull・Stiffness・届かないときに体が引かれる動き | 読んでいない | 再現しない（下の「やらないこと」） |

## 1. A0: Maya の結果と比べる道具

いまの FK・リターゲットも Maya の結果とは比べていません（[verification_status.md](verification_status.md)）。
A1 以降の式を決めるためにも、最初に作ります。

### 作るもの

- `tools/maya_hik_dump.py`（Maya のスクリプトエディタで実行する）
  - キャラクター（`HIKCharacterNode`）ごとに、部位のジョイント（`.ch` の接続）と、`HIKState2SK` で動くジョイントを集める。
  - 再生範囲（引数で範囲と間引きを指定できる）のフレームごとに、ジョイントのワールドの行列と、移動・回転の値を読む。
  - コントロールリグなら、FK のコントローラーと IK エフェクターのワールドの行列・Reach の値も読む。
    リターゲットなら、ソースのスケルトンのワールドの行列も読む。
  - HumanIK のプロパティ（`HIKProperty2State`）は、**全部の属性の名前・値・既定値**を書き出す
    （HumanIK は既定値のままの属性を .ma に書かないので、既定値はここでしか分からない。A2〜A4 で使う）。
  - 読み方は 2 通りを実装して、**両方の結果と時間**を書き出す（B1 の見積もりを兼ねる）。
    1. 時刻を指定した評価（`MDGContext`。タイムラインを動かさない）
    2. タイムラインを進めて読む（`cmds.currentTime`）
  - 出力は JSON 1 つ（ジョイントの名前・フレーム・行列・プロパティ・かかった時間・Maya の版・評価のモード）。
    メッシュ・ウェイトは入れない。
- `tools/hik_compare.py`（Maya なしで実行する）
  - 同じシーンの .ma をビューアの経路で評価し、上の JSON と比べる。
    部位ごとに、位置の差（cm）と向きの差（度）の最大・平均と、最大になったフレームを出す。
  - ビューアの評価は Node のテストと同じ入り口を使う（`web_src/tests/hik.test.mjs` の読み方）。

## 2. A1: コントロールリグの手足の IK エフェクター

### ねらい

全身にキーを打ったコントロールリグでは、キーの上では FK と IK の姿勢が一致し、キーの間でずれます
（FK は回転の補間、IK は位置の補間）。いまは FK だけなので、キーの間で足が滑ります。
手首・足首のエフェクターを 2 ボーン IK で近似すれば、いちばん目立つ差が埋まります。

### 対象

- 手首・足首のエフェクター（`LeftWristEffector`・`RightWristEffector`・`LeftAnkleEffector`・`RightAnkleEffector`）のうち、
  Reach（`.rt`・`.rr`）が 0 でない、またはキーのあるもの（いまの `ik_active` と同じ判定）。
- 肘・膝・腰・胸・肩・頭・手足の指先のエフェクター、補助エフェクター・ピボットは対象にしない
  （Reach が 0 でなければ、いまと同じ警告を出す）。

### 式（Q3〜Q5 で確かめてから決める。下は出発点）

部位のワールドの行列を、FK の結果（いまの `O · C`）から次のように直す。上腕（太もも）・前腕（すね）・手（足）の
FK の位置を p0・p1・p2、エフェクターの位置を E、向きを R_E とする。

1. 目標の位置: `T = p2 + ReachT · (E − p2)`
2. 骨の長さ `l1 = |p1 − p0|`・`l2 = |p2 − p1|` を保つ。目標までの距離は `d = clamp(|T − p0|, |l1 − l2|, l1 + l2)`
   （届かないときは腕・脚を伸ばしきる。体は引かない。警告に出す）。
3. 曲げる面は FK の面のまま。法線 `n = (p1 − p0) × (p2 − p0)`（まっすぐで決まらないときは、FK の前腕・すねの曲げる軸）。
   p1 のまわりで前腕・すねを n の軸で回し、`|p2′ − p0| = d` にする。
4. p0 のまわりで手足全体を回し、`p2′ − p0` の向きを `T − p0` の向きに合わせる（最小の回転）。
5. 手・足の向き: 3・4 のあとの向き（Q4 の結果で、FK のワールドの向きにするかを決める）と、
   エフェクターの向き `O_E · R_E`（`O_E` = スタンスのスケルトンの向き · スタンスのエフェクターの向き⁻¹。FK の `O` と同じ作り方）を、
   ReachR で球面補間する。

ReachT・ReachR が 0 なら FK と同じ結果になること（いまの結果を変えないこと）を、式の条件にします。

### 実装

- **部位のワールドの行列を、親子で矛盾しない形にする**（先に行う整理）。
  いまは部位ごとに `O · C` を別々に求めている。IK で手足の 3 部位のワールドが変わると、その子（指・つま先・ロール骨）も
  同じだけ動かす必要がある。子のワールドは `W_子(FK) · W_末端(FK)⁻¹ · W_末端(IK)` とする
  （`W_末端(FK)⁻¹` は `(コントローラー, "wim") · O⁻¹` で、いまの multMatrix の並びに足せる）。
- **手足を解くノード**: 入力は 3 部位の FK のワールドの行列・エフェクターのワールドの行列・ReachT・ReachR、
  出力は 3 部位のワールドの行列。作り方は次の順で検討する。
  1. 自作ノードの定義（[node_definitions.md](node_definitions.md)）の計算で書けるなら、同梱の定義にする
     （評価器・専用の評価・ワーカーに手を入れずに済む）。
  2. 書けなければ、ビューアの内部の型を 1 つ足す（`hik.py` が作り、`rig.js` の汎用の経路で評価する。
     `rigCompiled.js` は、まず「汎用の経路に任せる」でよい。速さが問題になったら専用の手順を足す）。
     共通 JSON・.msv に新しい型が入るので、[data_format.md](data_format.md) に書く。古い .msv は読めるままなので、形式の版は変えない。
- `hik.py`: `build_hik_rigs` のコントロールリグの枝で、対象のエフェクターのある手足だけ上のノードを通す。
  ReachT・ReachR はエフェクターの属性からつなぐ（キーで動く）。
- 警告・リグの診断: 「IK エフェクター（手足）を近似で評価する部位」を足す。
  「Reach が 0 でない IK エフェクター（FK の姿勢で表示）」は、対象にしないエフェクターだけにする。
- ポーズ確認: エフェクターを動かすと追従する（グラフにつなぐので、追加の実装は要らないはず。テストで確かめる）。

### テスト

- `tools/make_hik_sample.py` に、Reach が 1・0.5・キーで変わるエフェクターのキャラクターを足す。
- Python（`tests/test_hik.py`）: ノードの組み立て・警告・診断。
- Node（`web_src/tests/hik.test.mjs`）: ReachT = 0 で FK と同じ（ビット単位）・ReachT = 1 で手首がエフェクターの位置・
  骨の長さが変わらない・曲げる面が FK と同じ・届かないときに伸びきる・子（指）が手についていく・
  専用の評価と汎用の経路で同じ結果（`compiled.test.mjs`）。
- Maya: A0 の道具で、実装の前後の差を比べる（差が小さくなること）。

## 3. A2: リターゲットの足首・手首の位置合わせ

### ねらい

HumanIK のリターゲットは、既定で足首をソースの足首の位置（体格に合わせて縮めたもの）に合わせるはずです（Q8）。
いまは向きだけを移しているので、脚の長さの比がソースと違うキャラクターでは、足が浮く・滑ると考えられます。

### 式（Q2・Q8 で確かめてから決める）

- 足首の目標の位置: いまの腰と同じ作り方で、ソースの足首のスタンスからの動きを高さの比で縮め、ターゲットの足首のスタンスの位置に足す。
  `T = (ソースの足首の今の位置 − ソースの足首のスタンスの位置) · 比 + ターゲットの足首のスタンスの位置`
  （ソースのスタンスの空間で求め、ターゲットの基準の動き Dₜ を掛ける）。
- この目標に、A1 の手足を解くノードを通す（FK の入力は、いまのリターゲットの結果。Reach はプロパティの値）。
- 手首は、プロパティの Reach が 0 でないときだけ同じ処理をする（既定は 0 のはず）。

### 実装

- `hik.py`: プロパティのノード（`HIKProperty2State`。`HIKRetargeterNode`・`HIKSolverNode` の入力から見つける）の値を読む。
  .ma に書かれていない属性は、A0 で調べた既定値の表（`hik.py` に置く）を使う。
- リターゲットの枝で、足首（と手首）の Reach が 0 でない手足に、A1 と同じ組み立てを使う（A1 の整理が先）。
- 警告の文（「HumanIK のリターゲットの設定（…Reach…）は再現しません」）を、対応した範囲に合わせて直す。

### テスト

- 自作のサンプル（脚の長さの比がソースと違うターゲット）で、足首が目標の位置に来る・骨の長さが保たれる・
  Reach が 0 ならいまと同じ結果。
- Rokoko の DemoScene・GlovesScene（[verification_status.md](verification_status.md) で使っているもの）で、
  ソースのスタンスでバインドポーズと一致するまま（位置合わせを足しても、初期の姿勢が変わらない）。
- Maya: A0 の道具で、実装の前後の差を比べる。

## 4. A3・A4: ロール骨と床の接地

### A3: ロール骨・ひねりの分配

- HumanIK は、手首のひねりの一部を前腕に、前腕・すねなどのひねりをロール骨（`LeafLeftForeArmRoll1` など）に分けます。
  プロパティの割合で決まります（属性の名前・既定値は Q9）。
- いまは、ロール骨は「FK のコントローラーのない部位」として評価していません（ファイルの値で親についていく）。
- 式（出発点）: 子の部位の、親の骨の軸まわりのひねり（スイングとツイストに分けたツイスト）を取り出し、
  割合を掛けて、ロール骨（または親の部位）のローカルの回転にする。ロール骨のない部位に分けるときは、
  子のローカルから同じだけ引く（子のワールドの向きは変えない）。
- 割合がすべて 0（既定がオフ）なら、いまと同じ結果になること。
- 効果が出るのは、ロール骨・前腕にスキンのウェイトがあるモデルだけです。A0 の Q9 で既定がオフと分かり、
  手元のシーンで使われていなければ、後回しにします。

### A4: 床の接地

- 足（必要なら手）が床の高さより下に行かないように押し上げ、足首を A1 のノードで解き直します。
  床の高さは、床の接地のマーカー（`hikFloorContactMarker`）かプロパティで決まります（Q10）。
- つま先の曲げ・足の裏の傾きまで含めると、推定する式が増えます。**A0 の Q10 と実測の差を見てから、やるかを決めます**。
  やる場合も、足首の高さの下限だけ（つま先は曲げない）から始めます。

## 5. B1（先の予定）: Maya が評価した結果を取り込む

Maya からの転送のときに、`HIKState2SK` で動くジョイントの値をフレームごとに読み、キーとして渡します。
IK・床の接地・リターゲットの設定まで含めて Maya と一致する、ただ 1 つの方法です。A1〜A4 のあとに行います。

- **既定は近似のまま**にし、正確な結果がほしいときに選んで実行する機能にします（巨大なシーンでは時間がかかるため）。
  進み具合を出し、中止できるようにします。範囲は再生範囲・選んだキャラクターだけにできるようにします。
- 読み方は、時刻を指定した評価（タイムラインを動かさない。メッシュの変形・描画が走らない）を使います。
  使えるか・どれだけ速いかは A0 の Q11 で決まります。使えなければ、タイムラインを進めて読みます。
- 取り込んだ値は .msv に入れ、開き直したときに計算し直さないようにします。
- ポーズ確認でコントローラーを動かしたときは、取り込んだ値では追従できないので、近似（A1〜A4）で表示します。
- .ma を直接開く経路では使えません（Maya が要る）。
- 先に [maintenance_plan_2.md](maintenance_plan_2.md) の 3 章（H-1〜H-3）を片づけます。

## 6. やらないこと

| 内容 | 理由 |
|---|---|
| 全身のソルバー（Pull・Stiffness・届かないときに体が引かれる動き） | 計算式が公開されていない反復の解き方で、設定の組み合わせごとに合わせきれない。B1 で扱う |
| リターゲットの細かい設定（ソースへの一致の度合い・肩や胸の補正・足の間隔など） | 同じ |
| 補助エフェクター・ピボット | 使われることが少なく、式の推定が増える。Reach が 0 でなければ警告を出す |
| HumanIK の SDK の組み込み | いま単体では提供されていないはず（未確認）。配布の条件も合わない |
| 検証用の切り替え | 0 章の方針 |
